# Bad Case 复盘

## 方法

固定商品档案、问题、期望事实和目标来源，保留每轮答案与失败标签。先定位是否是实体、检索、片段上下文、排序还是生成遗漏，再增加回归用例。

## 翡翠场景：山水牌尺寸信息被遗漏

问题：“观山 P03 山水牌尺寸是多少？”初始生成器用问题中的“尺寸”筛选片段，商品档案的标题却是“规格与工艺”。尽管目标商品出现在重排结果中，生成阶段过滤掉了正确段落，引用了通用 SOP。

修正：统一规格/尺寸主题表达，将章节标题纳入主题判断，生成时使用完整父段。回归核对 42 mm、26 mm、5.5 mm 及对应商品来源。

## 多轮售后：运费问题继承商品但保留售后主题

问题链：“J01 多大”→“那它拆封能退吗”→“那退货运费谁出”。商品与售后主题同时保存；运费检索应召回通用退货政策，不能因商品名重复而优先回答尺寸。

修正：商品范围过滤与主题重排分别进行，通用售后文档参与召回。回归核对商品实体、returns 意图和“买家承担”。

## 内容生命周期：知识删除后再次启动

初始种子逻辑只判断知识数量，清空知识后重启会再次导入示例。修正为独立 seeded 元数据，确保运营删除的内容在重启后保持删除状态；索引同步删除对应向量。

## 持续闭环

前端“待改进”写入 feedback 表并显示在评测中心。Benchmark 自动生成 answer_fact_missing、retrieval_miss、intent_mismatch、route_mismatch，失败明细随报告保存。

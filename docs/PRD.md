# ShopDesk 翡翠智能客服 PRD

版本：1.0 · 2026-10-19

## 问题与目标

翡翠客服咨询高度依赖单件商品：同名手镯的圈口、重量、色带、档案和证书均可能不同。客户多轮追问常省略商品编号；售后又需要同时结合商品状态、店铺政策和沟通记录。平台将资料维护、问答、人工核对和反馈放入同一流程。

目标是缩短客服查找资料的路径、减少多轮重复询问、让人工接入时直接获得当前商品与已有对话。项目交付包括可操作工作台、API、领域知识、场景评测和部署材料。

## 用户角色

| 角色 | 主要任务 | 核心需要 |
|---|---|---|
| 买家 | 查询规格、圈口、证书流程、售后与订单状态 | 回答清晰，知道信息来自哪件商品 |
| 店铺运营 | 更新商品详情、FAQ、售后 SOP | 可启停、可版本化、更新及时生效 |
| 人工客服 | 接单、看货、证书与争议核对 | 带商品编号和诉求的交接摘要 |
| 产品/算法维护者 | 回看失败回答、比较链路版本 | 指标口径清晰，Bad Case 能定位环节 |

## P0 功能与验收

| 功能 | 行为 | 验收标准 |
|---|---|---|
| 单件咨询 | 按商品 ID 检索规格与档案 | J01 问题不能引用 B02 的参数 |
| 多轮追问 | 保存商品、主题与近期问题 | “那它拆封还能退吗”保留 J01 实体 |
| 知识管理 | 新建、编辑、启停、删除 | 保存版本递增，下一次问答更新索引，已删块消失 |
| 来源引用 | 展示出处与当前文档版本 | 来源 ID 必须在本次检索结果中 |
| 人工转接 | 主动请求、投诉、看货或实物判断 | 建立工单并附商品和对话摘要 |
| 工单处理 | 接入、处理、解决 | 路径为 open → in_progress → resolved，解决需说明 |
| 反馈闭环 | 有帮助/待改进 | 负向反馈进入 Bad Case 面板 |
| Benchmark | 固定场景与基线 | 自动生成指标、明细与失败标签 |

P1 包括接入真实商品中心、订单系统、正式身份认证网关及神经 Rerank 服务。当前提供这些服务的接口边界、配置和演示适配器。

## 核心用户故事

1. 买家问“J01 多大”，系统引用 J01 的尺寸和重量；随后问“那它能退吗”，系统引用 J01 售后提示及店铺规则。
2. 买家问“手腕 16 厘米适合这只吗”，系统创建人工核对工单，而不是直接根据圈口档案推定个体适配。
3. 运营修改现货发货时效，新版本在下一次问答进入索引。
4. 人工接入查看商品编号、此前咨询与本轮诉求，记录处理人并完成工单。
5. 产品维护者查看负向反馈，确认问题属于知识缺失、实体丢失、检索失配或答案遗漏，再加入回归集。

## 页面与状态

主导航：智能问答、知识库、人工转接、评测中心。问答页展示会话、聊天与证据；操作过程显示节点进度，发送期间禁用重复提交。

问答状态：answered、clarify、handoff。工单状态：open、in_progress、resolved。请求状态：running、completed、failed。知识状态：active / inactive，内容更新记录 version。

## 翡翠领域规则

- 每个实物以独立商品编号管理；规格、价格和档案按该件读取。
- 圈口内径与佩戴者测量值分开，个体适配由人工结合实物确认。
- 证书查询入口与该件证书/实物核对分开，演示编号均以 DEMO 标识。
- 标准现货与定制加工分别读取店铺约定。
- 实物颜色、纹裂、真伪、估价与交易争议交由人工核对，系统保存问题与证据线索。

## 指标与埋点

业务台展示累计完成轮次、有效知识数、转接轮次和平均响应。基准测试展示答案事实命中、意图/实体/路由准确率、Recall@3、P50 与 P95。

记录事件：session_created、intent、rewrite、retrieve、rerank、generate、handoff、feedback、knowledge_revision。运行节点与耗时随回答返回，知识变更通过版本与摘要关联。

## 验收路径

从无模型密钥的本地模式开始，依次执行商品问答、多轮售后、知识更新、人工接入、反馈和 Benchmark；再按部署文档接入实际服务，用相同的验收集检查接口行为。
